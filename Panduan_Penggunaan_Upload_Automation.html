Panduan Penggunaan Sistem Upload Automation

Otomasi Sinkronisasi Produk: Google Blogger (Dualtime ID) → Shopify Store (IDWX) & Google Sheets
File Utama: upload_automation.py Platform Eksekusi: PythonAnywhere (Always-on Task) Versi API: Shopify 2025-01 / Blogger v3 Pembaruan: Oktober 2026

1. Ringkasan & Arsitektur Sistem

Sistem Upload Automation dirancang untuk memantau artikel penjualan jam tangan baru di blog dualtime.id (Google Blogger) secara berkala, mengekstraksi metadata penting (Merek, Judul, SKU, Harga, Tahun, Spesifikasi, Kondisi, Foto High-Resolution), lalu mengunggahnya secara otomatis menjadi produk siap jual di Shopify Store (IDWX) serta mencatat laporannya ke Google Sheets via Webhooks.

Alur Eksekusi Otomatis (Setiap 5 Menit):
Blogger API → Filter Postingan Baru WIB → Klasifikasi Kategori → Ekstraksi Gambar & Metadata → Upload Shopify → Auto-Reconcile Foto → Update Status Webhook Sheets → Catat ke processed_urls.json.

2. Logika Klasifikasi Otomatis Format Postingan

Setiap artikel blogspot yang terdeteksi akan diperiksa label dan formatnya untuk menentukan perlakuan upload yang tepat:

Format / Tipe Kriteria Deteksi (Blogger) Perlakuan Shopify Integrasi Sheets
PHOTO STUDIO Label memuat CONSIGNMENT_PS Tags: __label2:Consignment, TitipIDWX, Gender Tag (Men/Ladies). Lokasi: Blok M Plaza Update status Publish di Spreadsheet Foto Studio via Webhook.
FEATURED Label memuat FEATURED Tags: Hanya Gender Tag (Men/Ladies). Lokasi: Blok M Plaza Kirim data produk ke Spreadsheet Slow Moving.
PHOTO OWNER Label memuat CONSIGNMENT_PO (atau awalan SKU CPO). Foto bisa 1 atau lebih. Tags: TitipOwner. Lokasi stok: OWNER (S). Mencentang kolom WEB di Spreadsheet Owner via Webhook.
NOTSYNC Label memuat NOTSYNC. Foto bisa 1 atau lebih. Tags: NotSync. Stok lokasi: Blok M Plaza. Tidak memicu webhook eksternal.
TWP Label memuat TWP (The Watch Project) Tags: SG. Stok lokasi: Blok M Plaza. Tidak memicu webhook eksternal.

3. Fitur Unggulan & Keandalan Sistem

1
Anti-Gagal Download Foto (Multi-Resolution Fallback): Sistem mendownload foto dengan User-Agent browser modern dan mencoba fallback resolusi bertingkat (/s0/ → /s2000/ → /s1600/ → /w1600/). Jika unduhan lokal di server mengalami kendala, sistem otomatis mengalihkan payload ke link src langsung ke CDN Shopify agar tidak ada foto yang terlewat.
2
Rekonsiliasi Foto Seketika (Auto-Reconcile): Tepat setelah produk berstatus HTTP 201 (Created), sistem langsung memverifikasi jumlah foto di Shopify. Jika ditemukan foto yang kurang (misal 6 dari 7), foto yang hilang diunggah ulang secara terisolasi via Product ID numerik seketika.
3
Auto-Refresh Token Shopify: Token akses Shopify disegarkan otomatis sebelum expired (tersisa < 10 menit) dan memiliki fitur auto-refresh seketika jika mendeteksi respons 401 Unauthorized, menjamin proses berjalan tanpa henti selama 24 jam.
4
Manajemen SKU & Handle Anti-Bentrok: Sistem menjaga keunikan SKU dan URL handle Shopify. Jika kode barang pernah dipakai sebelumnya di Shopify (misal barang konsinyasi lama), sistem otomatis memberikan penomoran unik (-1, -2, dst.) tanpa mengganggu data artikel Blogspot.

4. Panduan Menjalankan Sistem

A. Mode Otomatis 24 Jam (PythonAnywhere Always-on Task)

Mode ini adalah metode standar harian. Script akan terus memantau blogspot setiap 5 menit.

  1. Login ke akun PythonAnywhere Anda.
  2. Masuk ke tab Tasks → bagian Always-on tasks.
  3. Pastikan perintah yang dimasukkan adalah: 
    python3.10 /home/username/upload_automation.py
  4. Jika script sedang berjalan normal, Anda dapat melihat log real-time dengan mengklik ikon kertas (log file) di sebelah kanan task.

B. Mode Manual / Target URL Tertentu (Menggunakan Google Colab)

File upload_automation.py dikhususkan 100% berjalan otomatis 24 jam via Google Blogger API. Jika Anda memiliki postingan tertentu atau artikel masa lalu yang ingin di-upload secara manual on-demand, gunakan 4 File Script Notebook (.ipynb) di Google Colab:

  • auto_upload_photo_studio_(google_oauth).ipynb → Untuk format Photo Studio & Featured.
  • auto_upload_photo_owner_(google_oauth).ipynb → Untuk format Photo Owner (CPO).
  • upload_otomasi_format_notsync_(google_oauth).ipynb → Untuk format NotSync.
  • auto_upload_twp_(google_oauth).ipynb → Untuk format TWP (The Watch Project).

Panduan lengkap langkah demi langkah pengoperasian di Google Colab tersedia pada dokumen terpisah: Panduan_Penggunaan_Google_Colab.pdf.

5. Memahami File Pelacak Status (Cache JSON)

Script menggunakan 2 file JSON lokal untuk memastikan tidak ada artikel yang ter-upload ganda:

  • processed_urls.json: Menyimpan seluruh URL artikel blogspot yang sudah sukses ter-upload. Selama link ada di file ini, script tidak akan memproses ulang artikel tersebut.
  • processed_skus.json: Menyimpan daftar SKU yang diproses pada hari ini untuk mencegah postingan ganda di hari yang sama.

6. Panduan Pemecahan Masalah (Troubleshooting)

1. Error: invalid_grant: Token has been expired or revoked

Status Saat Ini (Sudah Teratasi): Aplikasi Google Cloud Console Anda saat ini sudah berstatus In Production dan Refresh Token yang terpasang bersifat permanen (tidak akan expired 7 hari lagi).

Langkah di bawah ini hanya sebagai panduan darurat jika di masa mendatang token sengaja dicabut (revoked) dari Google Account Security atau jika Anda mengganti akun project Google:

  1. Buka Google Cloud Console → pilih project → menu Audience (pastikan tetap In Production).
  2. Buka Google OAuth 2.0 Playground (developers.google.com/oauthplayground).
  3. Klik ikon ⚙️ Gear di kanan atas → centang Use your own OAuth credentials → masukkan GCP_CLIENT_ID dan GCP_CLIENT_SECRET Anda.
  4. Di Step 1, pilih scope https://www.googleapis.com/auth/blogger → klik Authorize APIs → login dan izinkan.
  5. Di Step 2, klik Exchange authorization code for tokens → salin Refresh token yang baru.
  6. Ganti nilai GCP_REFRESH_TOKEN pada script upload_automation.py atau file notebook.

2. Kenapa SKU di Shopify Bertambah Akhiran -1 atau -2?

Penjelasan: Teks di Blogspot tidak pernah diubah oleh script. Akhiran -1 atau -2 hanya ditambahkan pada produk Shopify karena kode SKU tersebut sudah pernah terdaftar di inventaris Shopify (misalnya barang konsinyasi lama dengan kode serupa). Ini fitur keamanan agar data inventaris di Shopify tidak saling menimpa.

3. Cara Restart Task Bersih di PythonAnywhere

Jika task mengalami error tak terduga dan perlu di-refresh:

  1. Buka tab Tasks di PythonAnywhere.
  2. Klik tombol Pause lalu Resume (atau tombol Stop / Start).
  3. Periksa log task melalui tombol View task log untuk memastikan pesan: Mendownload database SKU dan Handle dari Shopify... dan Autentikasi Google berhasil tanpa perlu login! sudah muncul.

4. Merek (Vendor) Salah Terdeteksi / Belum Terdaftar di Shopify

Tanda & Penyebab: Jika suatu produk berhasil ter-upload namun merek (vendor)-nya salah (misalnya hanya mengambil kata pertama dari judul atau menjadi Unknown), kemungkinan terbesarnya adalah merek jam tangan tersebut belum terdaftar di dalam dictionary DAFTAR_MEREK_IDWX pada script.

Langkah Penanganan:

  1. Tambahkan Merek Baru ke dalam Script: Buka file upload_automation.py (baris 41) pada bagian DAFTAR_MEREK_IDWX, lalu tambahkan merek baru tersebut mengikuti format: 
    DAFTAR_MEREK_IDWX = {
    # Format: "KEYWORD_HURUF_KAPITAL": "Format Nama Resmi Vendor",
    "GIRARD PERREGAUX": "Girard-Perregaux",
    "ORIS": "Oris",
    "HAMILTON": "Hamilton",
    ...
}
    • Bagian Kiri (Key): Wajib ditulis dalam HURUF KAPITAL / BESAR seluruhnya, karena sistem mencocokkannya menggunakan perbandingan huruf besar.
    • Bagian Kanan (Value): Ditulis dengan format nama resmi yang rapi sesuai tampilan yang Anda inginkan di kolom Vendor Shopify.
  2. Update Manual Produk yang Sudah Terlanjur Ter-upload di Shopify:
    Penting: Penambahan merek di script hanya berlaku untuk proses upload berikutnya. Untuk produk yang sudah terlanjur di-upload ke Shopify dengan merek yang keliru, Anda perlu mengoreksinya secara manual langsung di Shopify:
    1. Buka Shopify Admin → pilih menu Products.
    2. Cari dan klik produk yang mereknya salah.
    3. Pada panel sebelah kanan (bagian Product organization), ubah kolom Vendor ke nama merek yang benar.
    4. Klik tombol Save di pojok kanan atas.
